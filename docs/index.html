marine-backend-py：隨開發長出來的教材

marine-backend-py 是一個極簡的 FastAPI 後端，給開發 drone 容器的人在功能做完後手動測試用。 它站在瀏覽器（marine-frontend）和每台 drone 的 coordinator HTTP API 中間，讓你在網頁上看到 drone、讓它起飛、讓它降落。 它不是正式的地面站（GCS）：沒有資料庫、沒有認證、不接實機。 

瀏覽器 (marine-frontend)
   │  GET /api/drones                     ← 每 1 秒輪詢
   │  POST /api/drones/{name}/takeoff | land
   ▼
marine-backend-py  :8100                   ← 本 repo
   │  GET  /get_drone_state
   │  POST /api/takeoff | /api/land
   ▼
drone-N coordinator :7070  →  飛控（ArduPlane SITL）

專案照 ROADMAP.md 一步一步做，一個 step＝一個 PR＝一章。 每一章由寫那段程式的同一個人（同一個 session）在同一個 PR 裡寫成，所以章裡的輸出與數字都是實跑出來的， 踩過的坑也是真的踩過的。

名詞

  • coordinator：每個 drone 容器裡跑的 HTTP 服務（port 7070，來自 marlin-drone repo），把 HTTP 請求翻成送給飛控的 MAVLink 指令。
  • SITL（Software In The Loop）：在電腦上模擬的飛控與機體。這裡用 ArduPlane 的 quadplane（垂直起降）模型，每台 drone 一個 docker 容器；drone-1 的位址是 172.18.10.2。
  • 基線（baseline）：在改動之前先量下來的數字，存在 docs/baseline.md，之後每一步都拿來對照。

怎麼讀、怎麼跑

每一章都有「驗證」一節，裡面標著 貼上執行 的區塊是給你跑的指令，全部假設你站在 repo 根目錄：

git clone https://github.com/poyilee1030/marine-backend-py.git
cd marine-backend-py

需要主機上有 uv、curl、jq。會真的讓 drone 起飛的指令另外需要 SITL 在跑，章裡會明講。

本 repo 的腳本與測試 drone 的 coordinator（:7070） 飛控（ArduPlane SITL） 本後端（:8100）
